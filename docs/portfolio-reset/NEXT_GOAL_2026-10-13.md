# AI PM Radar — Next Goal (as of 2026-10-13)

## Goal

**P0 — Recover one daily-usable, owner-reviewed intelligence path** by tracing and repairing the smallest proven break in the existing workflow. This is a bounded repair, not a rebuild.

## Outcomes

- Primary: on the owner-used runtime, complete one public-safe record through intake, preservation, enrichment, evidence review, manual approval, export, and receiver readback.
- Secondary: establish the exact owner-runtime/source failure trace and retain a reproducible failure fixture if the full path cannot safely complete.
- Jev Shadow-mode is a separate later experiment; it is not part of this implementation slice.

## Acceptance criteria

1. Record exact app URL/runtime, branch/SHA or deployment revision, source fixture, and each UI/network/data/review transition without logging credentials.
2. A public-safe URL and a plain-text input are each accepted, preserved on reload, and have actionable unsupported-input fallback; if one cannot be repaired in the bounded slice, document the exact blocker.
3. One record preserves canonical source, original text, time, provenance, evidence links, and uncertainty across enrichment and review.
4. AI/provider failure leaves the original source intact and presents manual fallback; no result auto-verifies or approves a claim.
5. A human-approved package is exported and explicitly read back by an isolated synthetic receiver; export alone never sets `import_confirmed`.
6. Owner completes essential read/review tasks on the nominated mobile browser, or the device/runtime gap is explicitly Blocked.

## Non-goals

No Scoring vNext, universal crawler, unauthorized X/Threads scraping, push schedule, social autopost, Jev default routing, provider migration, schema change, deployment, or new paid API call. No private, employer, or customer data.

## Manual E2E

Use one synthetic/public-safe feed record and one pasted text record. Reproduce on owner-used runtime; follow intake → reload → enrichment (or deterministic fallback) → evidence inspection → explicit approval → immutable export → receiver UI import/readback. Capture screenshots/log excerpts with secrets redacted. Confirm manual path still works when AI is disabled.

## Security, cost, rollback gates

- Keep SourceRecord facts separate from derived analysis and preserve provenance.
- No secret/key inspection or logging; no new live API or schedule.
- If a repair changes local behavior, retain the current working-tree state and make a narrow reversible change only after the failure is reproduced; do not deploy or push.
- Any future Jev trial requires separate Owner authorization for SDK installation and a capped paid run, a 20-item labeled set, baseline comparison, cost/latency capture, and a fail-closed/manual fallback. Shadow output cannot alter records.
